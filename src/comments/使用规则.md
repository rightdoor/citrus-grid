# 评论适配器使用规则

本目录是 CitrusGrid 的评论适配器目录。站点主体不内置任何评论系统，只提供一套统一的浏览器端评论接口；具体评论能力由本目录下的适配器（每个评论系统一个独立 ts 文件）提供，类似换插头：把适配器放进本目录、在 `config.yaml` 里填上适配器名即完成接入，站点主体只依赖接口，不依赖任何具体评论系统。

## 一、启用与停用

在站点唯一配置源 `src/config.yaml` 中：

```yaml
# 评论适配器名（不含扩展名），对应本目录下的 <适配器名>.ts
commentScript: 'utterances'   # 启用：使用 src/comments/utterances.ts
commentScript: ''             # 停用（默认）：不渲染评论区，不注入脚本，不发任何请求
```

规则：

- 值为适配器文件名（不含 `.ts` 后缀），如 `utterances`；
- 留空则完全停用：页面不渲染评论区、浏览器不加载评论运行时、不发任何请求；
- 适配器名不合法或文件不存在时不会报错，只会输出控制台警告并按停用处理；
- 评论系统的私有配置（如 utterances 的 repo）**不写在 config.yaml**，写在对应适配器 ts 文件顶部的配置区（见第五节）。

## 二、目录结构

```text
src/comments/
├── client.ts          # 框架客户端运行时（勿动）：懒加载调度、适配器加载、占位状态机、主题转发
├── utterances.ts      # 适配器：utterances（GitHub Issues 评论），文件顶部为配置区
└── 使用规则.md         # 本文件
```

## 三、运行机制（框架侧 client.ts 保证）

| 机制 | 说明 |
| --- | --- |
| 懒加载 | 评论区挂载点由 IntersectionObserver 监听，临近视口（提前 300px）才加载适配器；评论位于首屏之下时首屏完全不请求评论资源。不支持 IntersectionObserver 的环境降级为立即加载 |
| 代码拆分 | `import.meta.glob` 让每个适配器成为独立 chunk，只拉取 config.yaml 指名的那一个；适配器模块会话级缓存，Swup 换页不重复拉取 |
| 预留占位 | 评论区由服务端渲染（最小高度 + shimmer 骨架），适配器渲染出首个内容节点后撤掉骨架，加载全程无布局跳动 |
| 异步加载 | 适配器 chunk 与第三方脚本（如 utteranc.es/client.js）均为异步注入，不阻塞页面 |
| 主题同步 | 运行时监听全局 `theme-change` 事件并转发给适配器的 `onThemeChange`，适配器自行同步给评论组件 |
| 换页兼容 | 每次页面加载（首次整页 + Swup 导航）都会重新执行挂载流程；换页销毁旧评论区前会调用适配器的 `unmountComment`（若导出） |
| 失败降级 | 适配器加载失败、未导出 `mountComment` 或挂载抛错：控制台输出警告，整个评论区隐藏（`is-error`），页面其余部分不受影响 |

预载距离与骨架兜底超时是 client.ts 顶部的常量（`LOAD_MARGIN` / `SKELETON_TIMEOUT`），可按需调整。

## 四、适配器接口契约（必须遵守）

适配器是一个普通的 TypeScript 模块，通过命名导出向运行时提供以下函数（不需要默认导出）。适配器运行在浏览器端，不要使用 Node 专有 API：

### 1. `mountComment(container)` —— 挂载评论（必选）

```ts
export function mountComment(container: HTMLElement): void | Promise<void>
```

- `container` 是评论挂载容器（评论区 `<section>` 内的 `.comment-mount` 空元素），把评论组件渲染进去即可；
- 配置不完整（如必填项为空）应直接抛错，由运行时统一隐藏评论区并输出警告；
- 应尽快返回（如只负责注入第三方引导脚本），第三方脚本的后续加载渲染由评论系统自行处理；
- 重入安全由运行时兜底（每次换页都是新容器），适配器无需自行去重。

### 2. `onThemeChange(dark)` —— 主题切换（可选）

```ts
export function onThemeChange(dark: boolean): void
```

- 运行时监听全局 `theme-change` 事件后转发，`dark` 为 `true` 表示切换到深色；
- 初始主题不经过此函数：`mountComment` 执行时应按当前主题（`document.documentElement.classList.contains('dark')`）自行初始化；
- 若评论组件不支持主题，不导出即可。

### 3. `unmountComment()` —— 换页清理（可选）

```ts
export function unmountComment(): void
```

- Swup 换页、评论区即将随旧 DOM 销毁前调用，用于清理定时器、全局监听器等；大多数适配器无需导出。

### 4. 错误处理约定（重要）

- 配置缺失、加载失败、挂载失败等情况应抛出异常，由运行时统一捕获后隐藏整个评论区；
- 不要用返回 `null` 等方式表达失败，直接 throw 即可。

## 五、配置区约定

各评论系统的私有配置写在适配器 ts 文件顶部的配置区，**不进 config.yaml**：config.yaml 的评论配置只负责「用哪个适配器」，即只有适配器文件名一项。配置区的字段命名与默认值由适配器自行定义，注释须写清每个字段的含义与填写方法。

## 六、页面挂载点（框架自动处理，适配器作者无需关心）

启用后 `src/components/Comments.astro` 在页面渲染评论区挂载点，client.ts 完成剩余工作：

| 挂载点 | 位置 | 结构 |
| --- | --- | --- |
| `<section data-comment-script="适配器名">` | PostPage 文末、FriendsPage 文末 | 内含 `.comment-skeleton` 骨架与 `.comment-mount` 挂载容器 |

骨架在挂载容器出现首个非 `script` 子节点（即评论组件真实内容）后移除，8 秒超时兜底强制移除，防止骨架卡死。

## 七、编写你自己的适配器（示例骨架）

以 giscus 为例，新建 `src/comments/giscus.ts`，再在 config.yaml 填 `commentScript: 'giscus'` 即完成接入：

```ts
// src/comments/giscus.ts —— config.yaml 填 commentScript: 'giscus' 即启用

// ========== 配置区 ==========
const config = {
  repo: '',
  repoId: '',
  category: '',
  categoryId: '',
  lightTheme: 'light',
  darkTheme: 'dark',
}
// ============================

const isDark = () => document.documentElement.classList.contains('dark')

export function mountComment(container: HTMLElement): void {
  if (!config.repo) throw new Error('[comments] giscus.repo 未配置')
  const script = document.createElement('script')
  script.src = 'https://giscus.app/client.js'
  script.async = true
  script.setAttribute('data-repo', config.repo)
  // ...其余 data-* 属性
  script.setAttribute('data-theme', isDark() ? config.darkTheme : config.lightTheme)
  container.appendChild(script)
}

export function onThemeChange(dark: boolean): void {
  document.querySelector<HTMLIFrameElement>('iframe.giscus-frame')?.contentWindow?.postMessage(
    { giscus: { setConfig: { theme: dark ? config.darkTheme : config.lightTheme } } },
    'https://giscus.app',
  )
}
```

注意事项：

1. `mountComment` 必选，`onThemeChange` / `unmountComment` 可选，只导出你需要的；
2. 适配器只在浏览器端运行，不会在构建期执行，停用时也不会被打包；
3. 适配器导出的一切都会打进浏览器 chunk，注意不要在配置区嵌入密钥等敏感凭证（评论系统所需的一般都是公开值）；
4. 文件名即适配器名，建议与评论系统同名（如 `giscus.ts`、`waline.ts`）。

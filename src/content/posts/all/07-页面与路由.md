## 1. 路由总表

所有页面均为构建期静态生成（Astro 默认 `output: 'static'`）。`src/pages/` 下共 16 个文件，对应下列路由：

| URL | 源文件 | 渲染组件 | `title` | 备注 |
| --- | --- | --- | --- | --- |
| `/` | `src/pages/index.astro` | `HomePage` | 无（用 `title - subtitle`） | 第 1 页 |
| `/{n}/`（n≥2） | `src/pages/[page].astro` | `HomePage` | `pagination.pageTitle` | 与首页共用组件，`filter(page > 1)` 排除第 1 页 |
| `/posts/{slug}/` | `src/pages/posts/[slug].astro` | `PostPage` | `post.data.title` | `seoType="article"`，`showTocButton` |
| `/archive/` | `src/pages/archive.astro` | `ArchivePage` | `archive.title` | 全部文章（置顶区 + 年份分组） |
| `/categories/` | `src/pages/categories/index.astro` | `TaxonomyPage`（`kind="categories"`） | `categories.title` | 搜索 + 排序 |
| `/categories/{分类名}/` | `src/pages/categories/[name].astro` | `ArchivePage` | `pageTitle.category` | 复用归档布局 |
| `/tags/` | `src/pages/tags/index.astro` | `TaxonomyPage`（`kind="tags"`） | `tags.title` | 标签云（与分类页共用组件） |
| `/tags/{标签名}/` | `src/pages/tags/[name].astro` | `ArchivePage` | `pageTitle.tag` | 复用归档布局 |
| `/series/` | `src/pages/series/index.astro` | `SeriesIndexPage` | `series.title` | 系列索引（系列名 + 篇数） |
| `/series/{系列名}/` | `src/pages/series/[name].astro` | `SeriesDetailPage` | `pageTitle.series` | 系列总览，按 `series_order` 升序 |
| `/friends/` | `src/pages/friends.astro` | `FriendsPage` | `nav.friends` | 底部带 `Comments` |
| `/about/` | `src/pages/about.astro` | `AboutPage` | `pageTitle.about` | 内容硬编码 |
| `/404.html` | `src/pages/404.astro` | 内联 | `404` | 静态托管兜底页 |
| `/rss.xml` | `src/pages/rss.xml.ts` | API Route | — | `@astrojs/rss` |
| `/robots.txt` | `src/pages/robots.txt.ts` | API Route | — | 指向 `sitemap-index.xml` |
| `/sitemap-index.xml`、`/sitemap-0.xml` | `@astrojs/sitemap` 集成 | — | — | 自动生成 |
| `/content-images/{hash}.{ext}` | `src/pages/content-images/[file].ts` | API Route（`prerender = true`） | — | 文章图片 |
| `/pagefind/*` | `pagefind` CLI（`postbuild.js`） | — | — | 搜索索引 |

> 三种动态路由的区别
>
> | 文件 | 动态参数来源 | 生成方式 |
> | --- | --- | --- |
> | `[page].astro` | Astro 的 `paginate()` 辅助函数 | `GetStaticPathsOptions.paginate` |
> | `posts/[slug].astro`、`categories/[name].astro`、`tags/[name].astro`、`series/[name].astro` | 文章 / 系列集合 | 手写 `getStaticPaths()` |
> | `content-images/[file].ts` | 文件系统遍历 | 手写 `getStaticPaths()`（`fs.readdir` 递归） |

## 2. 统一页面骨架

每个路由文件都是同一个模式（这是二次开发的入口约定）：

```astro
---
import XxxPage from '@/components/views/XxxPage.astro'
import { defaultLang, useTranslations } from '@/i18n/ui'
import BaseLayout from '@/layouts/BaseLayout.astro'
import { ... } from '@/lib/posts'

const lang = defaultLang
const t = useTranslations(lang)
const posts = await getPublishedPosts()          // ← 取数
const xxx = groupByXxx(posts)                    // ← 派生数据
---

<BaseLayout lang={lang} title={t('xxx.title')}>  {/* ← 布局 + SEO */}
  <XxxPage lang={lang} xxx={xxx} />              {/* ← 页面组件 */}
</BaseLayout>
```

要新增一个页面，照着这个模式写三块即可。默认导出内容为 `.astro` 模板，动态路由额外需要 `export async function getStaticPaths()`。

## 3. 各路由的取数逻辑

### 3.1 `index.astro`

```ts
const all = await getPublishedPosts()
const perPage = siteConfig.postsPerPage
const totalPages = Math.ceil(all.length / perPage) || 1
const posts = all.slice(0, perPage)
```

`|| 1` 保证无文章时总页数为 1（避免 `Pagination` 出现 0 页）。

### 3.2 `[page].astro`

```ts
export async function getStaticPaths({ paginate }: GetStaticPathsOptions) {
  const posts = await getPublishedPosts()
  return paginate(posts, { params: {}, pageSize: siteConfig.postsPerPage })
    .filter((p) => Number(p.params.page) > 1)      // ← 关键：排除第 1 页
}
```

| 细节 | 说明 |
| --- | --- |
| 为什么排除第 1 页 | 第 1 页由 `index.astro` 负责，否则 `/` 与 `/1/` 会生成重复内容 |
| 参数格式 | `paginate(posts, { params: {} })` → 路由为 `/{page}/` |
| 未分页时 | `posts.length <= perPage` 时 `paginate` 只返回 1 页，被 filter 掉 → 该路由不生成任何页面 |

### 3.3 `posts/[slug].astro`

```ts
export async function getStaticPaths() {
  const posts = await getPublishedPosts()
  return posts.map((post, idx) => ({
    params: { slug: post.id },                       // post.id 即 frontmatter 的 slug
    props: {
      post,
      prevPost: idx > 0 ? posts[idx - 1] : null,
      nextPost: idx < posts.length - 1 ? posts[idx + 1] : null,
    },
  }))
}
```

| 细节 | 说明 |
| --- | --- |
| `prev` / `next` 语义 | 按 `getPublishedPosts()` 的顺序（置顶优先，再时间倒序）取相邻项。`prevPost` 为列表中前一项（更靠前/更新） |
| 首尾处理 | 无上一/下一篇时传 `null`，`PostPage` 渲染为不可点击的占位块（`opacity-40`） |
| OG 图 | `post.body` 正则匹配第一张图：`/!\[[^\]]*\]\(([^)\s]+)/`，传给 `BaseLayout` 的 `seoImage` |

> 排序对「上一篇/下一篇」的影响
>
> 置顶文章（`index > 0`）会排在列表最前，因此它们的「下一篇」会指向置顶序列中的下一项，而不是时间上更新的文章。若你希望 prev/next 纯粹按时间，需要在 `getStaticPaths` 里单独按 `published` 排序一份列表。
>
> 有 `series` 的文章例外：`getStaticPaths` 会额外把同系列文章按 `series_order` 升序排成 `seriesPosts`，并计算当前文章的下标 `seriesIdx`。`PostPage` 有系列时用**系列内相邻**的上一/下一篇（首篇/末篇显示禁用态），与全局排序无关；无系列时仍走全局 prev/next。

### 3.4 `categories/[name].astro` 与 `tags/[name].astro`

```ts
// 分类
const names = [...new Set(posts.map((p) => p.data.category))]
return names.map((name) => ({ params: { name }, props: { name } }))

// 标签
const names = [...new Set(posts.flatMap((p) => p.data.tags))]
```

注意路径编码的不对称（容易踩坑）：

| 环节 | 编码处理 |
| --- | --- |
| 生成链接（`PostCard` / `PostPage` / `TaxonomyPage`） | `encodeURIComponent(name)` |
| `params` 传值 | 原始名（Astro 会自动编码到 URL） |
| 过滤 | `p.data.category === name` / `p.data.tags.includes(name)`（比较原始值） |

所以中文分类/标签能正常工作：URL 里是 `%E7%A4%BA%E4%BE%8B`，`params.name` 会由 Astro 解码回 `示例`。

> 若分类名里含 `/`，`encodeURIComponent` 会编成 `%2F`，但很多静态托管会在路由层解码后当作路径分隔符 → 建议分类/标签名不要包含 `/`。

### 4.3 JSON-LD 结构

```json
{
  "@context": "https://schema.org",
  "@type": "BlogPosting",
  "headline": "<文章标题>",
  "description": "<描述>",
  "image": "<og 图绝对 URL>",
  "datePublished": "<published ISO>",        // 仅当 publishedTime 传入时输出
  "dateModified": "<updated 或 published ISO>", // 仅当 modifiedTime 或 publishedTime 传入时输出
  "author": { "@type": "Person", "name": "<siteConfig.author>" },
  "publisher": {
    "@type": "Organization",
    "name": "<siteConfig.title>",
    "logo": { "@type": "ImageObject", "url": "<siteConfig.logo 绝对 URL>" }
  },
  "mainEntityOfPage": "<canonical URL>"
}
```

以 `is:inline` 内联脚本输出，不经过 `postbuild.js` 压缩（type 是 `application/ld+json`，不在 `JS_TYPES` 白名单）。

### 4.4 RSS（`src/pages/rss.xml.ts`）

| 字段 | 值 |
| --- | --- |
| `title` / `description` / `site` | `siteConfig` 对应值 |
| `customData` | `<language>{defaultLang}</language>` |
| 条目 | 每个已发布文章一条 |
| `link` | `/posts/{slug}/`（相对，由 `@astrojs/rss` 拼绝对） |
| `categories` | `[category, ...tags]` |
| `content` | `renderMarkdownHtml(post.body, { filePath, site })` 的输出 |

`absolutize()`：把内容里的相对 `src`/`href` 转为绝对 URL，基准是 `{site}/posts/{slug}/`。已跳过 `http(s):`、`data:`、`#`、`mailto:`、`//` 开头的值。

> RSS 用的是独立的 markdown 管线
>
> `src/lib/md/pipeline.ts` 与 `astro.config.mjs` 的 markdown 配置是两份独立的插件链，差异如下：
>
> | 项 | 页面（`astro.config.mjs`） | RSS（`pipeline.ts`） |
> | --- | --- | --- |
> | 插件来源 | Astro 的 `markdown.processor` | 手写 `unified()` |
> | 脚注标题 | 按 `defaultLang` 取 i18n 的 `post.footnotes` | 固定 `'footnote'` |
> | `rehypeRaw` | 由 Astro/remark-rehype 内部保留 raw 节点 | 显式 `.use(rehypeRaw)` |
> | `rehypeAutolinkHeadings` 的 `ariaLabel` | `'Heading anchor'` | `'heading anchor'`（小写 a） |
> | `gfm` / `smartypants` | 通过 `unified({ gfm: true, smartypants: false })` | 显式 `remarkGfm`，无 smartypants |
>
> 改 markdown 渲染时两份都要改，否则页面与 RSS 会出现差异。

## 5. i18n 现状与扩展

### 5.1 重要前提：只构建默认语言的页面

| 事实 | 证据 |
| --- | --- |
| 所有路由都写 `const lang = defaultLang` | `index.astro`、`archive.astro`、`posts/[slug].astro` … 全部如此 |
| `getLangFromUrl()` 没有任何调用点 | 全项目 grep 只在该函数定义处出现 |
| `localePath(lang, path)` 在 `lang === defaultLang` 时返回原路径 | 所以所有链接都不带语言前缀 |

结论：i18n 当前是「单语言站点 + 三套 UI 词条」。切换 `siteConfig.defaultLang` 会整体换掉界面文案，但不会同时提供 `/en/`、`/ja/` 路由。

### 5.3 取词 API（`src/i18n/ui.ts`）

URL 与语言判定统一在 `src/lib/url.ts`（`Lang` / `langs` / `defaultLang` / `getLangFromUrl` / `localePath` / `isAssetUrl` / `shouldIgnoreSwup`），`src/i18n/ui.ts` 转导出其中的语言常量与路径函数以兼容既有引用，取词函数 `useTranslations` 留在 `ui.ts`。

```ts
import { defaultLang, localePath, useTranslations, type Lang, langs, getLangFromUrl } from '@/i18n/ui'

const t = useTranslations('zh')
t('nav.home')                              // → '首页'
t('pagination.pageTitle', { n: 2 })        // → '第 2 页'（替换 {n}）
t('footer.running', { days: 30 })          // → '博客已运行 30 天'
t('不存在的.key')                           // → 原样返回 key（便于发现缺失）
```

| 导出 | 类型 | 说明 |
| --- | --- | --- |
| `Lang` | `'zh' \| 'ja' \| 'en'` | 语言类型（定义在 `src/lib/url.ts`） |
| `langs` | `Lang[]` | `['zh', 'ja', 'en']` |
| `defaultLang` | `Lang` | 来自 `siteConfig.defaultLang` |
| `getLangFromUrl(url)` | `(URL) => Lang` | 从路径首段判断语言（当前未被调用） |
| `localePath(lang, path)` | `(Lang, string) => string` | 生成带语言前缀的路径 |
| `useTranslations(lang)` | `(Lang) => (key, params?) => string` | 取词函数（`ui.ts` 自身导出） |
| `isAssetUrl(path)` | `(string) => boolean` | 资源 / 保留目录判定（无扩展名白名单外的 `.xml` `.json` `.png` 等，或 `/pagefind/` `/fonts/` `/images/` 前缀） |
| `shouldIgnoreSwup(url)` | `(string) => boolean` | Swup `ignore` 判定：带 `#` 或资源路径；`astro.config.mjs` 直接引用该函数 |

> `shouldIgnoreSwup` 必须自包含
>
> `@swup/astro` 会把传给它的 `ignore` 函数序列化成源码、在浏览器里用 `eval` 还原（`@swup_astro_serialise.js` 的 reviver），因此函数体内不能引用模块作用域的变量或常量（V1.0.9 之后把判定集中到 `lib/url.ts` 时踩过：改成调用 `isAssetUrl()` 后每次加载都抛 `ReferenceError: isAssetUrl is not defined`，Swup 的预加载判定随之失效）。所以 `shouldIgnoreSwup` 内部直接写正则字面量，`isAssetUrl` 与它规则相同但仅供程序内调用，不要改成互相引用。

`t()` 的内部实现：按 `.` 拆 key 逐层下钻；非字符串结果回退为 key 本身；`{param}` 用 `replaceAll` 替换。

`localePath()` 的行为：

```ts
localePath('zh', '/about')      // → '/about/'      （默认语言不加前缀，补尾斜杠）
localePath('en', '/about')      // → '/en/about/'
localePath('zh', '/rss.xml')    // → '/rss.xml'     （含 . 的最后一段视为文件，不补斜杠）
localePath('zh', '/')           // → '/'
localePath('en', '/')           // → '/en'
```

### 5.4 加一门语言（以韩语 `ko` 为例）

> 完整的多语言路由需要自行实现。
>
> 下面只完成「词条与类型」部分。要真正产出 `/ko/…` 页面，需要为每个路由写语言维度：
>
> ```ts
> export async function getStaticPaths() {
>   return langs.flatMap((lang) =>
>     posts.map((post) => ({
>       params: { lang, slug: post.id },      // 需要把路由挪到 src/pages/[lang]/ 下
>       props: { post, lang },
>     })),
>   )
> }
> ```
>
> 并把 `src/pages/*.astro` 移入 `src/pages/[lang]/`（默认语言可用 `[...]` 可选参数或单独保留一份）。这是一次结构性改动，建议先确认是否真的需要。

仅换界面语言（最小成本）：

1. `src/i18n/ko.json` —— 复制 `zh.json` 并翻译（key 结构必须完全一致）；

2. `src/i18n/ui.ts` —— 三处改动：

    ```ts
    import ko from './ko.json'
    export type Lang = 'zh' | 'ja' | 'en' | 'ko'
    export const langs: Lang[] = ['zh', 'ja', 'en', 'ko']
    const messages: Record<Lang, Record<string, unknown>> = { zh, ja, en, ko }
    ```

3. `src/site.config.ts` —— `defaultLang: 'ko' as 'zh' | 'ja' | 'en' | 'ko'`（注意 `Lang` 联合类型也要同步）；

4. `astro.config.mjs` —— 脚注标题映射：

    ```js
    const footnoteLabel = { zh: zhJson, ja: jaJson, en: enJson, ko: koJson }[siteConfig.defaultLang].post.footnotes
    ```

5. `BaseLayout.astro` —— OG locale 映射：`{ zh: 'zh_CN', ja: 'ja_JP', en: 'en_US', ko: 'ko_KR' }`；

6. `ProfileCard.astro` —— 数字本地化：`{ zh: 'zh-CN', ja: 'ja-JP', en: 'en-US', ko: 'ko-KR' }[lang]`。

漏改第 4/5/6 项不会报错，但会静默回退（脚注标题变 `undefined`、OG locale 报错）。建议加完语言后跑一次 `pnpm check` 与 `pnpm build` 并检查文章页与首页。

## 6. 新增页面与导航项

### 6.1 加一个静态页面（例：`/guestbook/`）

第 1 步：创建页面组件 `src/components/views/GuestbookPage.astro`

```astro
---
import Comments from '@/components/Comments.astro'
import { defaultLang, type Lang, useTranslations } from '@/i18n/ui'

interface Props { lang?: Lang }
const { lang = defaultLang } = Astro.props
const t = useTranslations(lang)
---

<div class="mx-auto mt-8 max-w-[800px]">
  <header class="mb-8 text-center">
    <h1 class="font-serif text-[1.75rem] font-bold text-ink">{t('nav.guestbook')}</h1>
  </header>
  <Comments />
</div>
```

第 2 步：创建路由 `src/pages/guestbook.astro`

## 8. Swup 无刷新导航与页面脚本

### 8.1 生命周期钩子对照表

| 钩子 | 触发时机 | 项目中的用途 |
| --- | --- | --- |
| `astro:before-swap` | 新 DOM 即将替换旧 DOM | 移除容器外的 `#toc-affix`；重置导航高亮；卸载评论适配器（`comments/client.ts`）。搜索弹窗不在此关闭 |
| `astro:after-swap` | DOM 已替换 | 重新应用主题（`theme.ts`）；同步 TOC 按钮显隐（`BaseLayout`）；关闭搜索弹窗（`SearchModal`） |
| `astro:page-load` | 页面完全就绪 | `onPageLoad()` 回调；同步导航状态 |
| Swup `visit:start` | 开始导航 | `syncNavState(目标路径)` 提前更新高亮 |
| Swup `visit:end` | 导航结束 | （未使用） |

### 8.2 写页面脚本的正确方式

```ts
import { onPageLoad } from '@/lib/pageLifecycle'

function initMyFeature() {
  const root = document.getElementById('my-root')
  if (!root) return
  if (root.dataset.bound) return       // ← 幂等保护，防止重复绑定
  root.dataset.bound = '1'
  // ...
}

onPageLoad(initMyFeature)
```

`onPageLoad()` 的实现（`src/lib/pageLifecycle.ts`）：

```ts
export function onPageLoad(init: () => void) {
  document.addEventListener('astro:page-load', init)
  if (window.__pageLoadFired) init()      // ← 脚本在 page-load 之后才执行时补跑一次
}
```

| 要点 | 说明 |
| --- | --- |
| 为什么要补跑 | Swup 换页时，从新页面加载的 `<script>` 可能在 `astro:page-load` 之后才执行 |
| `__pageLoadFired` | 由 `BaseLayout` 的脚本设置（`page-load` 时 `true`，`before-swap` 时 `false`） |
| 幂等 | `onPageLoad` 不保证只调用一次，回调内部必须自己做幂等保护（如 `dataset.bound`） |

### 8.3 未使用 Swup 的地方

以下情况会跳过 Swup（`ignore` 规则命中）。注意「跳过 Swup」不等于「必须整页刷新」：

- 含 `#` 的 URL：同页锚点（正文标题锚点、目录）由 `PostPage` 内容区拦截平滑滚动；跨页锚点由 `BaseLayout` 点击委托接管为 SPA 导航 + 加载后平滑滚动（见 [8.4](#84-跨页锚点链接的平滑跳转)），都不会闪现
- 静态资源扩展名（见 [04-站点配置.md#3.3](./04-站点配置.md#33-integrations-swup-与-sitemap)）
- `/pagefind/`、`/fonts/`、`/images/` 开头的路径

> 需要强制整页刷新时
>
> 给 `<a>` 加 `data-no-swup` 属性（Swup 的内置约定），或在 `astro.config.mjs` 的 `ignore` 回调里加规则。

### 8.4 跨页锚点链接的平滑跳转

跨文章/跨页面的锚点链接（如 markdown 相对链接 `[标题](./05-内容与Markdown.md#9-文章页面的-toc目录)`，会被 `rehypeRelativeLinks` 转成 `/posts/05-nei-rong-yu-markdown#9-文章页面的-toc目录`）：

1. `BaseLayout` 的点击委托发现「同源 + 带 `#` + 目标路径 ≠ 当前路径」的内部链接 → `preventDefault()`；
2. 锚点 id 记到 `window.__pendingScrollHash`，`swup.navigate()` 用去掉 hash 的 URL 导航，换页自然落在页顶；
3. `astro:page-load` 时 `consumePendingScrollHash()` 把 hash 写回地址栏（可分享/刷新），120ms 后按目录同款 80px 偏移（`HEADING_SCROLL_OFFSET`）平滑滚动到标题。

同时覆盖「直接打开深链接」（收藏/分享的带 `#` URL）场景：`<head>` 里一段内联脚本先记录锚点并去掉 URL 上的 hash，阻止浏览器原生闪现定位，随后走同样的平滑滚动。

搜索结果的章节级跳转复用同一机制：`SearchModal` 的 `go()` 在跨页时把锚点写入 `__pendingScrollHash` 再导航；同页命中则直接调用 `window.__scrollToHeadingAnchor`（`BaseLayout` 暴露的同款平滑滚动）原地滚动，不经换页。

| 要点 | 说明 |
| --- | --- |
| 同页锚点不受影响 | 目标路径 == 当前路径时点击委托直接返回，仍由 `PostPage` 内容区/目录的 `smoothScrollToHeading()` 处理 |
| 尊重用户操作 | `meta/ctrl/shift/alt` 修饰键、非左键、`data-no-swup`、外站链接一律放行（保持原生行为） |
| 降级 | 无 `window.swup` 时回退 `location.assign(原 href)`；`prefers-reduced-motion: reduce` 时降级为瞬时定位 |
| 锚点容错 | 与目录一致：先按原始 id、再按 `decodeURIComponent(id)` 查找 |
| 想改回原生闪现 | 删掉 `BaseLayout.astro` 内联去 hash 脚本与底部脚本里的点击委托 + `consumePendingScrollHash()` |

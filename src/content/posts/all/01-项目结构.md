> 为什么没有 `tailwind.config.js`？
>
> Tailwind v4 采用 CSS-first 配置。主题扩展写在 `src/styles/main.css` 的 `@theme inline { ... }` 块中，暗色变体用 `@custom-variant dark (&:where(.dark, .dark *))` 声明。
>
> 新增设计 token 请加在 `main.css`，不要试图新建 tailwind 配置文件。

## 3. 构建流水线（按执行顺序）

```text
┌─ astro build ───────────────────────────────────────────────────────
│
│  ① Vite 插件 buildStart 钩子（astro.config.mjs → vite.plugins）
│     ├─ ensurePostSlugs()     扫描 md，补全缺失的 slug，写 .generated/post-index.json
│     │
│     ├─ generateLqips()       扫描 md 中的图片，sharp 取 3 点主色，写 .generated/lqips.json（增量，LQIP_FORCE=1 全量）
│     │
│     └─ updatePostUpdated()   按文件 mtime 回写 frontmatter 的 updated（仅当 siteConfig.autoUpdatePostUpdated）
│
│
│  ② 内容集合加载（src/content.config.ts 的 Zod schema 校验 frontmatter）
│                                                                          
│  ③ 页面渲染（src/pages/**）
│     ├─ Markdown → HTML：remark 链 + 自定义 rehype 链（见 05 文档）
│     └─ 全站预渲染为 dist/**/*.html（output 默认 static）
│
│  ④ Vite 打包：esbuild 压缩 JS、lightningcss 压缩 CSS、资源哈希
│
└────────────────────────────────────────────────────────────────
                                    │
                                    ▼
┌─ node scripts/postbuild.js ──────────────────────────────────────────────
│  ├─ 并行启动 pagefind --site dist（生成 /pagefind/ 搜索索引）
│  ├─ 遍历 dist/**/*.html：压缩所有「内联且无 src」的 JS（esbuild）
│  └─ 读取每个 HTML 里 module script 引用的 chunk，解析 __vite__mapDeps，把依赖 chunk 以 <link rel="modulepreload"> 注入 <head>
└────────────────────────────────────────────────────────────────
```

流水线的副作用：构建会改写 `src/content/posts/` 里面的 markdown 文件（补 slug、写 updated）。这是有意为之，但意味着构建后 `git status` 可能有变动，建议先 `pnpm build` 再 `git commit`。

## 4. 数据流：一篇文章从文件到页面

```text
src/content/posts/示例.md
   │
   │  frontmatter 经 content.config.ts 的 Zod schema 校验 / 归一化
   │  （category 取数组首项；tags 支持 "a,b" 字符串或数组，去重去空）
   ▼
CollectionEntry<'posts'>  ──►  src/lib/posts.ts
   │                            ├─ getPublishedPosts()  生产环境过滤 draft，排序：index 降序 → published 降序
   │                            ├─ wordCount() / readMinutes()（400 字/分钟，最少 1 分钟）
   │                            ├─ excerptOf()  description 优先，否则正文前 120 字
   │                            └─ groupByCategory / groupByTags / groupByYear
   ▼
src/pages/*.astro  ──(props)──►  src/components/pages/*.astro
   │                                   │
   │                                   └─ PostCard / ArchivePage 等消费
   ▼
BaseLayout.astro
   ├─ 组装 <title> / OG / Twitter Card / canonical / JSON-LD
   ├─ 内联「防闪烁」主题脚本（读取 localStorage.themeMode）
   └─ 渲染常驻 UI：SiteHeader、slot、SiteFooter、SearchModal、ScrollControls、MusicPlayer
```

### 排序规则（很重要，改首页顺序时看这里）

`src/lib/posts.ts` 的 `getPublishedPosts()`：

```ts
posts.sort((a, b) =>
  b.data.index - a.data.index ||                                  // 先按置顶权重降序
  b.data.published.valueOf() - a.data.published.valueOf()         // 再按发布时间降序
)
```

即 `index > 0` 的文章按数值越大越靠前，`index === 0` 的文章按时间倒序。

## 5. 常驻 UI 与 Swup 容器边界

Swup 只替换 `#swup-container` 的内容（`astro.config.mjs` 的 `containers: ['#swup-container']`）。`BaseLayout.astro` 的结构：

```html
<div class="flex min-h-screen flex-col">
  <SiteHeader />                                    <!-- 常驻，不重建 -->
  <div id="swup-container" class="transition-swup-fade flex flex-1 flex-col">
    <main class="wp-glass ...">                      <!-- ★ 只有这里被替换 -->
      <slot />
    </main>
  </div>
  <SiteFooter />                                    <!-- 常驻 -->
  <SearchModal />                                   <!-- 常驻 -->
  <ScrollControls />   <!-- 注释明确说明：放在容器外，避免切页抖动 -->
  <MusicPlayer />      <!-- 注释明确说明：放在容器外，保证切页不停止播放 -->
</div>
```

> 二次开发提示：
>
> 如果你想新增一个「切页时不重建」的元素（如自定义悬浮挂件、在线客服），放进 `#swup-container` 之外，并在 `astro.config.mjs` 的 `swup.ignore` 回调里确认相关资源不会被 Swup 拦截。

Swup 的 `ignore` 规则（`astro.config.mjs`）会跳过以下 URL：

| 规则 | 说明 |
| --- | --- |
| 含 `#` | 锚点链接跳过 Swup：同页锚点（标题锚点、目录）由内容区平滑滚动；跨页锚点由 `BaseLayout` 点击委托接管为 SPA 导航 + 平滑滚动（见 [07-页面与路由.md#84](./07-页面与路由.md#84-跨页锚点链接的平滑跳转)） |
| 扩展名为 `xml/txt/json/pdf/zip/png/jpg/jpeg/webp/gif/svg/ico/avif/woff/woff2/ttf/eot` | 静态资源，不做 SPA 导航 |
| 路径以 `/pagefind/`、`/fonts/`、`/images/` 开头 | 索引与资源目录 |

## 6. 路径别名与代码规范

`tsconfig.json`：

```json
{
  "extends": "astro/tsconfigs/strict",
  "compilerOptions": {
    "baseUrl": ".",
    "resolveJsonModule": true,
    "paths": { "@/*": ["src/*"] }
  }
}
```

组件内统一用 `@/` 引用（`@/components/Icon.astro`、`@/lib/posts`、`@/site.config`），不要写 `../../` 相对深层路径。

`biome.json` 关键规则：

| 项 | 值 |
| --- | --- |
| 缩进 | 2 空格 |
| 行宽 | 100 |
| 引号 | 单引号 |
| 分号 | `asNeeded`（不写多余分号） |
| Lint 预设 | `recommended` |
| `.astro` 覆盖 | 关闭 `noUnusedVariables` / `noUnusedImports` |
| CSS 解析 | 开启 `tailwindDirectives`（识别 `@theme`、`@custom-variant`） |

## 7. `.generated/` 派生数据说明

| 文件 | 生成者 | 结构 | 消费者 |
| --- | --- | --- | --- |
| `post-index.json` | `scripts/ensure-post-slugs.js` | `[{ "file": "posts/示例.md", "slug": "shi-li", "draft": false }]` | `src/lib/md/rehypeRelativeLinks.ts`（把 `./其他.md` 转成 `/posts/其他-slug/`） |
| `lqips.json` | `scripts/generate-lqips.js` | `{ "/content-images/883d9fc6f4cc516e.webp": "632d1b6a301b582816" }`（3 点主色直接拼接，18 位无分隔符十六进制） | `src/lib/md/rehypeImages.ts`（生成 `--img-lqip` 渐变） |
| `post-updated.json` | `scripts/update-post-updated.js` | `{ "示例.md": { "mtime": 1730000000000, "stamp": "2026-01-01 00:00:00" } }` | 同脚本，用于判断文件是否在同步后又被保存 |

> 这三个文件丢了会怎样？
>
> 删掉后重新构建即可自动重建。`lqips.json` 丢失只会让首屏图片占位从「主色渐变」退化为「灰白 shimmer」，不影响构建成功。

本文覆盖 `src/components/` 下全部 19 个 Astro 组件（`src/components/` 10 个通用组件 + `src/components/pages/` 9 个页面级组件）与 1 个布局。

> 组件分层约定
> 项目把组件分成两层，理解这一点能省很多力气：
>
> - 页面级组件 `src/components/pages/*.astro`：承载某个页面的完整内容（标题区、列表、空状态），只接收数据 props；
> - 路由文件： `src/pages/*.astro`：只做「取数据 → 传给页面组件 → 包一层 BaseLayout」的薄封装。
>
> 所以「改页面长相」去 `components/pages/`，「改 URL 或取数逻辑」去 `src/pages/`。

`PostPage` 的三个补充说明

1. CSS 按需注入：`katex/dist/katex.min.css` 只有在正文出现 `.katex` 时才注入，`photoswipe/style.css` 只有在正文有图片、真要初始化灯箱时才注入。两者都用 `?inline` 取 CSS 文本后写入 `<style data-…-css>`，因为 `astro.config.mjs` 的 `build.inlineStylesheets: 'always'` 会把动态 import 出来的 CSS 资源内联进每个文章页 HTML 并删掉资源文件（无公式 / 无图片的页面也会被内联，且公式页会多出一个 404 请求）。

2. 系列目录当前项：浅色模式为 `bg-accent/10 text-ink` + 左侧 `border-l-2 border-accent` 竖条（实测对比度 11.97:1）；暗色模式维持原样 `dark:text-accent` 且不描边（4.91:1）。早先的 `text-accent` 浅色下仅 4.48:1，不达 WCAG AA 4.5:1。

3. 拆分：系列目录与上下篇导航分别抽成 `SeriesToc.astro` / `PostNav.astro`；客户端逻辑抽到 `lib/photoswipe.ts`（灯箱）、`lib/postActions.ts`（复制按钮 + 锚点滚动）、`lib/postContent.ts`（图片框载入态 + 滚动淡入）、`lib/postToc.ts`（目录定位 / 折叠 / 当前项跟踪），`PostPage.astro` 只保留数据计算、视图组合与 `onPageLoad` 编排。

## 2. 基础原子组件

### 2.1 `Icon.astro`

```astro
<Icon d={mdiCalendarOutline} class="text-sm" />
```

| Prop | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `d` | `string` | 是 | — | SVG `<path>` 的 `d` 属性，来自 `src/lib/icons.ts` 的导出常量 |
| `class` | `string` | 否 | — | 追加到根 `<svg>`，会与 `mdi-icon` 类合并 |

输出结构：

```html
<svg class="mdi-icon text-sm" width="1em" height="1em" viewBox="0 0 24 24"
     fill="currentColor" aria-hidden="true"><path d="…"></path></svg>
```

要点：

- 尺寸用 `1em`，所以通过字体大小 class 控制图标大小（`text-sm` / `text-lg` / `text-[11px]`）；
- 颜色继承 `currentColor`，跟随文字色；
- 固定 `aria-hidden="true"`，装饰性图标不进无障碍树。需要语义时请在父元素上写 `aria-label`（如 `ScrollControls` 的 `title`）。

### 2.2 客户端字符串版本 `iconSvg()`

有些地方需要在构建期拼 HTML 字符串（代码块头部、复制按钮），不能渲染组件，于是 `src/lib/icons.ts` 提供了同名函数：

```ts
import { iconSvg, type IconName } from '@/lib/icons'
iconSvg('mdi-content-copy')          // → '<svg class="mdi-icon" …></svg>'
iconSvg('mdi-check', 'text-green')   // 第二参数追加 class
```

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `name` | `IconName` | `icons` 映射表的 key，kebab-case 全名 |
| `cls` | `string` | 追加 class，默认 `''` |

## 3. 常驻组件（位于 `#swup-container` 之外）

### 3.1 `SiteHeader.astro`

| Prop | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `lang` | `Lang` | `defaultLang` | 取词语言 |

导航项 = 注册表 + 配置白名单两级：`SiteHeader.astro` 内的 `NAV_DEFS` 登记每个可用 path 的词条 key 与图标，`siteConfig.nav`（字符串数组）决定「显示哪些、什么顺序」；首页 `/` 固定第一位、不可移除，无需写入配置：

```ts
// src/site.config.ts
nav: ['/archive', '/categories', '/tags', '/series', '/friends', '/about'],

// SiteHeader.astro
const navConfig = siteConfig.nav ?? []                              // 缺失/类型非法时回退空数组
const navItems = [
  { path: '/', label: t('nav.home'), icon: mdiHomeOutline },        // 固定第一项
  ...[...new Set(Array.isArray(navConfig) ? navConfig : [])]
    .filter((path) => path !== '/' && path in NAV_DEFS)             // 去重、忽略未登记的 path
    .map((path) => ({ path, label: t(NAV_DEFS[path].key), icon: NAV_DEFS[path].icon })),
]
```

> 现有导航页（`/archive` ~ `/about`）只需在 `siteConfig.nav` 里增删/排序，空数组 `[]` 则顶栏只剩首页一项；新增自定义页面还要在 `NAV_DEFS` 登记词条 key 与图标 + 在三个 i18n 的 JSON 里加对应 `nav.*` 词条。图标来自 `src/lib/icons.ts`（MDI path 常量）。

结构要点：

| 元素 | 关键 class / 属性 | 说明 |
| --- | --- | --- |
| `<header>` | `sticky top-0 z-[100]`；内联 `background-color: var(--wp-header-bg)` + `backdrop-filter: blur(3px)` | 毛玻璃吸顶。背景色改 `--wp-header-bg` |
| 桌面导航 `<nav>` | `absolute left-1/2 -translate-x-1/2 max-md:hidden` | 绝对居中、项间无间隔，与左右两侧 Logo / 菜单互不影响；md 以下切换为汉堡菜单 |
| 导航项 | `.nav-item` + `data-nav-path={localePath(lang, item.path)}` | 初始只显示图标；宽度以 `.nav-label` 文字为基准恒定（图标绝对定位覆盖、不参与布局），hover 前后宽度不变，响应式切换无布局抖动；`data-nav-path` 供 `BaseLayout` 的 `syncNavState()` 做高亮；hover 背景板被 `.nav-clip` 裁剪在 `--nav-window`（默认 60×60）固定窗口内；zh 双字加 padding 后项宽≈60px，窗口天然相贴。窗口尺寸只有一个来源：`.nav-item` 上的 `--nav-window: 60px`，`.nav-clip` 的宽高与 `.nav-compact .nav-content` 的宽度都取它，`fitNavLabels()` 也运行时读它。词条宽于「`--nav-window` − 4px」（默认 56px，左右各留 2px 余量）时（如 en/ja），`fitNavLabels()` 按「最宽词条」算出统一缩放比例、全组同字号缩小（下限具名常量 `MIN_FONT_SIZE = 10px`，Web 字体加载完成后复校一次），并给每项加 `.nav-compact` 类把 `.nav-content` 固定为 `--nav-window` 宽、去掉横向 padding，使 clip 窗口与项同宽、相邻项背景板无缝相贴；词条不缩写、字号一致，zh 不触发、完全不变 |
| hover 背景板 | `.nav-clip > .nav-board`（组件内 `<style>`） | hover / `:focus-visible` 时主题色矩形板（无圆角、`inset: 0` 高度宽度占满整个导航项）从上方拉下（`translateY(-101%) → 0`），下拉与收起统一用 `cubic-bezier(0.4, 0, 0.2, 1)` 平滑缓动，无回弹 |
| 图文替换 | `.nav-icon`（原生 `<span>` 包裹 `<Icon>`，绝对定位居中）与 `.nav-label`（常驻布局、`opacity` 显隐） | 常态只显示居中图标；触发时图标先完全淡出（0.16s）、名称再淡入（延迟 0.16s），两个方向都先出后进、任意时刻绝不同时可见，hover 只显示居中文字；背景为主题色、文字变白。注意 Astro 作用域样式不穿透子组件，`<Icon>` 必须包一层原生 `<span>` 才能被组件内 `<style>` 命中 |
| 当前项常驻 | `.nav-item.text-accent` 复用 hover 全部样式 | `syncNavState()` 切换的 `text-accent` 即状态钩子，无需改 JS；继续 hover 无变化 |
| 兜底项 | `data-nav-path="__fallback__"` | 当没有任何导航项匹配当前路径时，由它承接[全部取消高亮]的状态 |
| 移动端 | `hidden max-md:block` 容器内 `<details class="group relative">` + `<summary>` + 绝对定位面板 | 纯 CSS/HTML 折叠菜单，无 JS 状态；md 以下替代桌面导航 |

交互脚本（`SiteHeader.astro` 底部 `<script>`）：点击 `header details` 外部时移除 `open` 属性关闭菜单；同一脚本内的 `fitNavLabels()` 按 `--nav-window` 缩放导航词条（选择器限定为 `header nav .nav-label`），并在 `document.fonts.ready` 后再复校一次。

首页高亮特例：`isHomePaged = /^\/\d+(\/|$)/.test(currentPath)`，即 `/2/`、`/3/` 这类分页路径也视为[首页]高亮。

### 3.2 `SiteFooter.astro`

| Prop | 类型 | 默认 |
| --- | --- | --- |
| `lang` | `Lang` | `defaultLang` |

构建期取最早一篇文章的发布时间，运行时长（天/时/分/秒）由客户端脚本每秒实时计算。`published` 在 `content.config.ts` 中按 UTC 解析（无时区字符串补 `Z`），因此存储的是真实 UTC 时刻；运行时长 = 访问者当前 UTC（`Date.now()` 即 UTC epoch）− 发布 UTC，不依赖构建机、也不依赖访问者的本地时区，所有访问者看到一致的结果：

```ts
// 构建期：只确定起点，并把初始时长写进页面作为无 JS 的回退显示。
// earliest 已是真实 UTC 时刻（schema 层按 UTC 解析）
const publishedPosts = await getPublishedPosts()
const earliest = publishedPosts.reduce<Date | null>(
  (min, p) => (min === null || p.data.published < min ? p.data.published : min),
  null,
)
function breakdown(ms: number) { /* …拆分天/时/分/秒… */ }
const buildUnits = earliest ? breakdown(Date.now() - earliest.valueOf()) : null
```

```ts
// 客户端：当前时间与最早文章时间的差值实时计算，精确到秒（<script> in SiteFooter.astro）
function breakdown(ms: number) {
  const total = Math.max(0, Math.floor(ms / 1000))
  return {
    days: Math.floor(total / 86400),
    hours: Math.floor((total % 86400) / 3600),
    minutes: Math.floor((total % 3600) / 60),
    seconds: total % 60,
  }
}
function updateRunningTime() {
  document.querySelectorAll<HTMLElement>('[data-running-days]').forEach((el) => {
    const iso = el.dataset.earliest
    const template = el.dataset.template
    if (!iso || !template) return
    const u = breakdown(Date.now() - new Date(iso).getTime())
    const text = template
      .replaceAll('{days}', String(u.days))
      .replaceAll('{hours}', String(u.hours))
      .replaceAll('{minutes}', String(u.minutes))
      .replaceAll('{seconds}', String(u.seconds))
    if (el.textContent !== text) el.textContent = text
  })
}
updateRunningTime()
document.addEventListener('astro:page-load', updateRunningTime)
// 每秒刷新，秒位实时跳动；重复执行时只挂一个定时器
if (!('__runningTimeTimer' in window)) {
  ;(window as any).__runningTimeTimer = setInterval(updateRunningTime, 1000)
}
```

| 显示项 | 条件 | 文案 key | 备注 |
| --- | --- | --- | --- |
| `© {year} {author} All rights reserved` | 总是 | — | 年份取构建时的 `new Date().getUTCFullYear()`，作者链接指向 `siteConfig.url` |
| `Powered by Astro & CitrusGrid` | 总是 | — | 纯静态文本 |
| RSS / Sitemap 链接 | 总是 | `footer.rss` / `footer.sitemap` | RSS 走 `localePath(lang, '/rss.xml')`；Sitemap 硬编码 `/sitemap-index.xml` |
| 运行时长（天/时/分/秒） | `earliest` 存在（即至少有一篇文章） | `footer.running`（`{days}` `{hours}` `{minutes}` `{seconds}` 占位） | 无文章时不显示 |

> 运行时长的实现细节：
>
> - `<p data-running-days>` 上挂 `data-earliest`（ISO 时间，带 `Z`，构建期写入）和 `data-template`（当前语言的 `footer.running` 文案），服务端先渲染构建期算好的初始值。
> - 完全实时，不受构建固定：首次加载、Swup 换页（`astro:page-load`）、以及每秒的定时器都会用客户端当前时间与最早文章时间的差值重算四个单位；仅文本变化时写 DOM，避免无谓重排。页面一直开着，秒位也会实时跳动并自动进位。
> - 语义为"经过的时长"（毫秒差拆分为天/时/分/秒），时区无关。

搜索结果渲染的字段（与 Pagefind 返回结构对应）：

```ts
item.url              // 结果链接（页面级，无 hash）
item.meta?.title      // 标题（缺省回退到 url）
item.excerpt          // 页面级摘要（Pagefind 自带高亮 <mark>），仅在没有子结果时兜底显示
item.sub_results      // 章节级子结果：按带 id 的 h1~h6 拆分页面，命中多的章节优先
//   sub.url         // 形如 /posts/xxx/#章节id（中文锚点已百分号编码）
//   sub.title       // 章节标题（首个无锚点子结果是页面本身，渲染时跳过）
//   sub.excerpt     // 该章节内的高亮摘录
//   sub.anchor      // { element, id, text, location }，用于去重与回退取标题
```

> `excerpt` 是 Pagefind 生成的 HTML，未经 `escapeHtml`，这是有意为之（保留高亮 `<mark>`，用 `[&_mark]:` 任意属性选择器上主题色）；`url` 与 `title` 走了 `escapeHtml`。

> 结果卡片结构：文章标题（点击进文章顶部）→ 分隔线 → 命中章节列表（最多 `MAX_SUB_RESULTS` 条，点击滚动到对应标题）。文章无带 id 的标题时退化为「标题 + 页面级摘录」。

| 项 | 实现 |
| --- | --- |
| 按钮 | `.card-toggle`：42×42 直角方块（`border-radius: 0`），位于社交条 `.social-strip` 最左端、作为首个流式子项与右侧社交块并入一个整体（无 `margin`/`gap`，相邻方块经 `.social-strip > * + * { border-left: none }` 共用竖线，条内零间隙），`border-top: none` 与全条同规范共用卡片底边，整排居中（`position: relative` 只为给 `::before` 色板提供包含块，wrapper 已去掉 `pt-8`，各断点同一位置）；hover/focus 走顶栏 nav-clip 同款色板动效（主题色 `translateY(-101%) → 0` 拉下、0.5s `cubic-bezier(0.4, 0, 0.2, 1)`，图标同步转白）；图标在 `mdi-clock-outline` / `mdi-account-outline` 间切换，同步更新 `aria-pressed`、`aria-label` 与 `title`（词条 `profile.showClock` / `profile.showProfile`，三语齐全）；`title` 必须与 `aria-label` 一起同步，否则鼠标悬停看不到提示（`aria-label` 不产生可视 tooltip，社交块用的是 `title`，两者表现要一致）；按钮已移出 `.card`，`initProfileCardClock` 改从 `.profile-card` 根节点查 `data-clock-toggle`，克隆件不再包含按钮（`sync()` 无需同步按钮 innerHTML） |
| 时钟层 | `.clock-layer` 绝对覆盖整卡，自身为容器（`container-type: inline-size`）供内部用 `cqw` 取卡片宽；面板底色为主题色 4%→15% 竖向渐变，与卡片 `--wp-surface` 错开，保证刷漆竖条扫过时特效可见（底部更浓模拟湿漆）；默认 `clip-path: inset(0 0 100% 0)` 完全裁掉。内容整体双向居中（`justify-content: center` + `align-items: center` + `padding: 10px 16px`），三行：时区（`Intl…timeZone` + UTC 偏移）、七段数码管时分秒、`Intl.DateTimeFormat` 年月日星期（locale 由 `data-locale` 传入） |
| 数码管 | 每位 7 个 `<i data-seg="a…g">`，段位用多边形 `clip-path` 切出外观：横段（a/g/d）两端 45° 倒角、倒角距离 = 段厚一半（`--seg-t / 2`），竖段（f/b/e/c）用同一多边形旋转 90°（坐标 `(x,y)→(y,x)`），倒角同角同长、接缝形状一致（倒角不能按元素长度百分比裁，横竖两段长宽比不同会角度错位）；数字宽高比 5 : 8（`W ≈ 0.625×seg-h`，横段长 ≈ 0.435×seg-h、竖段长 ≈ 0.375×seg-h）；竖段高 `50% − seg-t/2 − 2×seg-gap`（尖端探到 `H/2 − G`，四角与中段共 8 处接缝菱形间隙全部一致）；亮/灭只切背景色（`--seg-on` 主题色 / `--seg-off` 8% 文字色），尺寸由 `--seg-h: clamp(36px, 10.75cqw, 140px)` 等比派生（时钟行总宽 ≈ 4.85×seg-h ≈ 50% 卡片宽，随卡片等比缩放、高度同步拉长；内容整体居中呈现，移动端兜底 36px）；冒号 1s 周期闪烁（即 500ms 亮、500ms 灭） |
| 刷漆动画 | 卡片宽度按 28px 均分竖条（`round(W/28)`，实测 27.3–28px，整宽铺满不留缝）；每条竖条自上而下被裁掉，相邻条错峰 25ms 依次推进（左→右），单条 480ms，总时长 `480 + (N-1)×25`。用一个「阶梯多边形」`clip-path` 表达所有竖条的合成形状，等价于逐条裁切但不复制 DOM。同一套关键帧也在预览方窗的克隆层上同跑，方窗才会与本体同步刷过（见下方「动效同步」） |
| 反向 | 时间轴倒放（关键帧数组反转 + `offset` 取补）：竖条从右到左重构覆盖层，裁切方向与正向完全相反 |
| 时钟常驻 | 时钟不受动画影响，`setTimeout` 对齐秒边界持续走时，`visibilitychange` 回到前台立即补算；月日/时区变化时才写 DOM |
| 可达性 | 时钟层 `aria-hidden="true"`；时钟态给卡片加 `.is-clock`，底层内容 `visibility: hidden`，配合 `.clock-layer.is-on { pointer-events: auto }` 屏蔽底层点击 |
| 降级 | `prefers-reduced-motion: reduce` 时跳过动画直接切换；动画进行中忽略重复点击；按钮尺寸与动画时长无关 |

另一套主题预览镜头（鼠标划入首页名片，`ProfileCard.astro` + `main.css` 的共享 `.card-preview` 样式块）：方窗里不是色块，而是把卡片克隆一份、整体套上相反主题 token 后的真实渲染——即「访客切到暗夜 / 白天模式时这张名片长什么样」。

| 项 | 实现 |
| --- | --- |
| 结构 | 卡片内第一个子节点是空的 `.card-preview` 覆盖层（`position: absolute; inset: -1px`、`overflow: hidden`、`border-radius: 12px`、`pointer-events: none`、`inert`、`aria-hidden="true"`）；克隆件由脚本在加载期一次性生成并常驻复用（图片提前解码，指针划入时窗口直接是满的） |
| 逐像素对齐 | 卡片有 1px 边框，覆盖层用 `inset: -1px` 向外各扩 1px 正好等于卡片外框；克隆件 `.card-preview-clone` 用 `box-sizing: border-box; width: 100%` 撑满覆盖层，字体 / 头像 / 内边距 / 圆角与本体一致，窗口内外内容无缝接续 |
| 反色 | 克隆根节点加 `.dark`（当前亮色模式时）或 `.light`（当前暗色模式时）：`.dark` 是暗色 token 块，`.light` 与 `:root` 同级（`main.css` 的 `:root, .light`），于是克隆内部所有 `--wp-*` 都取到另一套主题的值，Tailwind `dark:` 变体（`&:where(.dark, .dark *)`）随之生效 |
| 方窗 | 覆盖层用 `clip-path: inset(上 右 下 左)` 只留指针处 56×56 的窗口，四个 insets 由 `--preview-x` / `--preview-y`（指针在覆盖层内的坐标）算出，窗口随指针走；外层 `overflow: hidden` + 12px 圆角把窗口裁在卡片形状内 |
| 常驻 | 只切换 `opacity`（`.card-preview.is-on`）：划入后一直保持，没有淡出/涟漪动画；指针移出名片（或卡片被 `hidden`）才熄灭。时钟模式下方窗照常唤起：`sync()` 会把根类名 `is-clock`、时钟层 `is-on` 与数码管段位类一起同步进克隆，方窗里显示的是反色时钟（亮段 `--wp-accent` 取克隆自身变量，随反主题翻转） |
| 跟随 | `pointermove` 记下指针视口坐标，与覆盖层 `getBoundingClientRect()` 原点相减写入变量 → 方窗中心始终对准指针，连续平滑跟随、不吸附 28px 网格 |
| 克隆同步 | 脚本加载期就 `card.cloneNode(true)` 生成克隆并常驻（先剔掉克隆里的 `.card-preview` 防递归，并剥掉 `data-stats` / `data-clock-*` 等 JS 挂载点，避免外部脚本把克隆件当成真实挂载点往里写；`data-stats` 处保留 `class="stat-live"` 作同步钩子）。此后永不重建：`sync()` 只就地改根类名（`is-clock` / `.dark` / `.light`）、段位 on 类、时区/日期/PV/UV 文本 —— 换新 `<img>` 要等解码，重建产生的空帧在方窗里就是「头像闪烁」，常驻克隆从根上杜绝。主题变化经 `theme-change` 立即同步；指针静止时 250ms 定时器同步走秒，移动时每帧顺带同步 |
| 动效同步 | 刷漆期间克隆层跟着跑同一套关键帧：`card.querySelectorAll('.clock-layer')` 里除本体外就是克隆层（克隆已剥掉 `data-clock-*`，只按类名选中），克隆与本体逐像素重合、同一 tick 创建即共享时间轴，方窗因此和本体同步刷过。缺这一步的话克隆层只能在 `is-on`（全显）与默认（全裁）之间二选一、没有中间态，整段动效里方窗都会停在切换前的画面，直到 `settle()` 才跳变。`onfinish` 中 `settle()` 之后派发 `profile-card-clock-settle`，预览侧收到立即 `sync()`（把落定的 `is-on` 同步进克隆）——只等 250ms 定时器会在方窗里残留旧画面；动画 `cancel()` 与克隆同步都在这一处收尾 |
| 事件与节流 | 仅响应鼠标（`pointerType === 'mouse'`）；`requestAnimationFrame` 合并高频 `pointermove`，每帧最多写一次；`scroll` / `resize` 重测原点；首次划入先测原点、再就地同步、再摆窗口，避免淡入首帧闪到左上角 |
| 可达性 | 覆盖层 `aria-hidden` 且 `inert`（无 Tab 焦点、不进无障碍树）、`pointer-events: none`（鼠标事件直穿本体），克隆件里的按钮/链接不会产生重复操作点 |
| 降级 | `prefers-reduced-motion: reduce` 时 `.card-preview` 直接 `display: none`，脚本也不激活 |

预览方窗（与名片同一套机制，`PostCard.astro` + `main.css` 共享块 + `PostCard.css`）：每张文章卡同样内嵌 `.card-preview` 覆盖层（`position: absolute; inset: -1px`、`overflow: hidden`、`pointer-events: none`、`inert`），鼠标划入时用 `clip-path: inset(...)` 露出指针处 56×56 方窗，窗口里是反主题克隆：

| 项 | 实现 |
| --- | --- |
| 极简克隆 | `build()` 在 `cloneNode(true)` 后剔除 `.card-badge`（置顶 / 分类 / 更新时间角标）与 `.card-actions`（PV/UV 徽标、「前往阅读」），克隆只保留标题 / 系列 / 日期 / 摘要 / 标签正文——方窗内不骑边、不含统计挂载点（`data-stats` 节点随 `.card-actions` 整体移除，无需像名片那样剥属性） |
| 悬停镜像 | 预览层 `pointer-events: none`，克隆永远收不到 `:hover`；`pointermove` 用 `closest('[data-hover]')` 命中真实卡的标题 / 系列 / 标签链接（模板里带 `data-hover="title|series|tag"` 标记），按 `hoverables` 数组序号映射到克隆对应节点加 `.preview-hover` 类，`reset()` 时清除 |

| 同步与节流 | 与名片同构（`build` / `measure` / `render` / `reset` / `move` / `leave` / `refresh`），`sync()` 只就地改根类名（`card.className + card-preview-clone + 反主题类`），没有统计 / 时钟文本要同步；`rAF` 合并高频 `pointermove`，仅响应鼠标（`pointerType === 'mouse'`），`prefers-reduced-motion` 下 `main.css` 直接 `display: none`、脚本不激活 |

### 4.10 `MusicPlayer.astro`

| Prop | 类型 | 默认 | 说明 |

代码结构（T10 拆分后）：`MusicPlayer.astro` 只留视图（面板 / 列表 / 控制条 DOM）与事件绑定，逻辑分三处：

| 模块 | 职责 |
| --- | --- |
| `src/lib/player.ts` | 播放状态机与纯逻辑：当前曲目、播放 / 暂停、播放模式、音量、上下曲索引、进度换算（`createPlayer()`）；对外只依赖 `MediaPort` 端口，不碰 DOM |
| `src/lib/musicUi.ts` | DOM 助手：元素查询（`queryPlayerElements()`）、音频端口实现（`createMediaPort()`）、视图更新（`createPlayerViewFrom()`）、面板 / 列表动画、滚动条与浮动定位 |

播放列表来源（两级优先）：

| 优先级 | 条件 | 行为 |
| --- | --- | --- |
| 1 | `siteConfig.musicPlayer.playlist.length > 0` | 直接用配置的列表（可自定义 `title` / `cover` / 顺序） |
| 2 | 配置为空数组 | 构建期扫描 `public/music/`，按文件名 `localeCompare(a, b, 'zh')` 排序生成列表 |

扫描支持的扩展名（源码 `src/lib/musicPlaylist.ts` 的 `AUDIO_EXTS`）：

```text
# 已验证
.flac  .mp3

# 未验证
.m4a  .ogg  .wav  .opus  .aac  .webm
```

自动生成的条目：`title` = 去扩展名的文件名，`src` = `/music/${encodeURIComponent(文件名)}`（中文名会被 URL 编码）。

> `audioCover.ts` 的 `FETCH_LIMIT = 2 * 1024 * 1024`（2MB），若你的音频封面位于 2MB 之后会取不到（极少见）。

## 4A. 图标系统（`src/lib/icons.ts`）

全站图标硬编码在 `src/lib/icons.ts`：66 个 `export const mdiXxx = '<path d>'` 常量，加一个 `icons` 映射表（kebab-case 名 → path）与两个导出。

设计取向（源码注释 + `添加自定义图标.md`）：零网络请求、零依赖，代价是加图标要手写三步。

### 4A.1 三个导出

| 导出 | 类型 | 用途 |
| --- | --- | --- |
| `mdiXxx` | `string`（SVG path 的 `d`） | 组件里按名 import 后传给 `<Icon d={…} />` |
| `icons` | `as const` 对象 | kebab-case 全名 → path，供字符串场景使用 |
| `IconName` | `keyof typeof icons` | 类型约束（`iconSvg()` 的入参类型） |
| `iconSvg(name, cls?)` | `(IconName, string) => string` | 构建期拼 HTML 字符串（代码块头部、复制按钮用） |

```ts
export function iconSvg(name: IconName, cls = ''): string {
  return `<svg class="mdi-icon${cls ? ` ${cls}` : ''}" width="1em" height="1em" viewBox="0 0 24 24" fill="currentColor" aria-hidden="true"><path d="${icons[name]}"></path></svg>`
}
```

### 4A.2 添加图标的三个步骤

第 1 步：在 [MDI 图标库](https://pictogrammers.com/library/mdi/) 复制 SVG path，按字母序粘贴到 `src/lib/icons.ts` 顶部：

```ts
export const mdiAbTesting = 'M4 2A2 2 0 0 0 2 4V12H4V8H6V12H8V4…'
```

第 2 步：在文件底部的 `icons` 映射表加条目（key 必须是 kebab-case 全名，与常量名对应）：

```ts
export const icons = {
  // ...
  'mdi-ab-testing': mdiAbTesting,
} as const
```

第 3 步：在组件里使用

```astro
---
import Icon from '@/components/Icon.astro'
import { mdiAbTesting } from '@/lib/icons'
---

<Icon d={mdiAbTesting} class="text-sm" />
```

或在构建期拼字符串：`iconSvg('mdi-ab-testing')`。

> 漏掉第 2 步会类型报错
>
> `IconName = keyof typeof icons`，只加常量不加映射时，`iconSvg('mdi-ab-testing')` 会 TS 报错。

### 5.4 防闪烁主题脚本（`<head>` 内联）

```js
var stored = localStorage.getItem('themeMode')
var mode = (stored === 'light' || stored === 'dark') ? stored : defaultTheme
if (mode !== 'light' && mode !== 'dark') {                 // 即 defaultTheme === 'auto'
  mode = window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light'
}
document.documentElement.classList.toggle('dark', mode === 'dark')
document.documentElement.style.colorScheme = mode
```

> 这段脚本必须在 `<head>` 同步执行，否则会出现「先白后黑」闪烁。改主题逻辑时不要把它改成 module 或挪到 `<body>` 末尾。

### 5.5 `#swup-container` 外的脚本职责（`src/lib/client/*`）

`BaseLayout.astro` 底部只有一行 `<script>import '@/lib/client'</script>`，实现按职责拆到 `src/lib/client/`（入口 `index.ts` 按下列顺序执行）：

| 模块 | 内容 |
| --- | --- |
| `pageBindings.ts` | `initTheme()`、page-load 标记、`syncTocFab()`、右下按钮组菜单、控件点击委托 |
| `swupBindings.ts` | `syncNavState()`、`bindNavStartSync()`、换页前后钩子、跨页锚点与 pending hash |
| `profileCardAnim.ts` | 首页名片（`#profile-card-root`）进出场动画 |
| `gridTrail.ts` | 鼠标划过网格背景轨迹 |

各绑定与迁移前一致（逐段搬运）：

| 函数 / 监听 | 作用 |
| --- | --- |
| `initTheme()` | 初始化主题（来自 `stores/theme.ts`） |
| `syncTocFab()` | 依据当前页是否存在 `#toc-affix` 决定右下目录按钮显隐；在 `astro:after-swap` 与 `astro:page-load` 两个时机各同步一次，避免竞态 |
| `syncNavState(path?)` | 遍历 `a[data-nav-path]`，用 `text-accent` / `text-ink-2` 切换高亮；处理 `__fallback__`；关闭 `header details[open]` |
| `bindNavStartSync()` | 绑定 Swup 的 `visit:start` 钩子，让导航高亮在跳转开始就更新（最多重试 100 次 × 100ms，等待 `window.swup` 就绪） |
| `bindProfileCardAnim()` | 绑定名片进出场钩子：Swup 已就绪直接绑定，否则监听一次 `swup:enable` 或最多重试 20 次 × 100ms（迁移前为 100 次轮询） |
| `astro:before-swap` | 移除容器外残留的 `#toc-affix`（重新 append 到 body），并同步导航状态 |
| 点击委托 | `[data-scroll-menu]` 切换整合菜单展开/收起；`[data-backtop]` 平滑回顶；`[data-open-search]` 派发 `open-search`；`details.md-container-details` 的 `summary` 点击时播放折叠动画（用 Web Animations API 从 `scrollHeight` 动画到 0，然后移除 `open`） |
| 跨页锚点点击委托 | 拦截「同源 + 带 `#` + 跨路径」的内部链接：锚点记到 `window.__pendingScrollHash`，`swup.navigate()` 用去掉 hash 的 URL 导航到页顶（无 swup 时回退 `location.assign`）；修饰键、非左键、`data-no-swup`、外站链接放行 |
| `consumePendingScrollHash()` | `astro:page-load` 时消费待滚动锚点：hash 写回地址栏，120ms 后 `smoothScrollToHeadingAnchor()` 平滑滚动（80px 偏移，同目录；`prefers-reduced-motion` 降级为瞬时） |
| `window.__scrollToHeadingAnchor` | `smoothScrollToHeadingAnchor()` 的全局暴露，供 `SearchModal` 的同页锚点跳转复用 |

跨页锚点（`/posts/xxx#slug`）的平滑滚动由上述「跨页锚点点击委托」+ `consumePendingScrollHash()` 实现；配合 `<head>` 里一段内联「去 hash」脚本，直接打开收藏/分享的 `#` 深链接同样不闪现。完整流程见 [07-页面与路由.md#84](./07-页面与路由.md#84-跨页锚点链接的平滑跳转)。

## 6. 全局事件与 data 属性协议速查

改组件或加组件时，沿用这些约定就能自动接入现有交互：

### 6.1 自定义事件

| 事件 | 派发者 | 监听者 | 用途 |
| --- | --- | --- | --- |
| `open-search` | `BaseLayout`（点击 `[data-open-search]`） | `SearchModal` | 打开搜索弹窗 |
| `theme-change` | `stores/theme.ts` 的 `applyTheme()`，`detail` 为 `'light' \| 'dark'` | `comments/client.ts`（转发给适配器 `onThemeChange`）、`ProfileCard` 预览分支（立刻把克隆件的 `.dark` / `.light` 换过来，不等下一次指针移动或定时器） | 主题切换通知 |
| `profile-card-clock-settle` | `ProfileCard` 时钟分支的 `onfinish`（在 `settle()` 之后派发） | 同文件的 `initProfileCardPreview()` | 刷漆落定后立即把 `is-clock` / `is-on` 同步进克隆件；只靠 250ms 定时器会让方窗在动效结束后残留一帧旧画面 |
| `astro:page-load` | Astro / `lib/client` 补发（模块在 DOMContentLoaded 前注册） | `lib/pageLifecycle.ts` 的 `onPageLoad`、多处初始化 | 页面（含 Swup 换页）就绪 |
| `astro:after-swap` | Swup / Astro | TOC 按钮显隐同步（`BaseLayout`）、主题重应用（`theme.ts`）、关闭搜索弹窗（`SearchModal`）。注意：目录弹窗 `#toc-modal` 无人监听此事件 | DOM 已替换 |
| `astro:before-swap` | Swup / Astro | 移除容器外残留的 `#toc-affix`（只 remove，append 由 `PostPage` 的 `initPage()` 负责）、重置导航状态、卸载评论适配器 | DOM 即将替换 |

> 新增常驻脚本的正确姿势：
>
> 在 `.astro` 里写 `<script>`，并用 `onPageLoad()` 包裹初始化：
>
> ```ts
> import { onPageLoad } from '@/lib/pageLifecycle'
> function initMyWidget() { /* 幂等初始化 */ }
> onPageLoad(initMyWidget)
> ```
>
> `onPageLoad` 会同时监听 `astro:page-load` 并在「本次加载已经触发过」时立即执行，避免 Swup 换页后脚本不跑。

# 统计脚本（插件）使用规则

本目录是 CitrusGrid 的统计插件目录。站点本身不内置任何统计服务，只提供一套浏览器端注入接口；统计能力由本目录下的脚本（插件）提供，类似插件机制：把脚本放进本目录、在 `site.config.ts` 里填上脚本名即完成接入。

## 一、启用与停用

在站点唯一配置源 `src/site.config.ts` 中：

```ts
// 统计脚本名（不含扩展名），对应本目录下的 <脚本名>.ts
statsScript: 'visitor-stats',  // 启用：加载 src/stats/visitor-stats.ts
statsScript: '',               // 停用（默认）：不注入任何脚本，页面无统计挂载点，也不发统计请求
```

规则：

- 值为脚本文件名（不含 `.ts` 后缀），如 `visitor-stats`；
- 留空（默认）则完全停用：页面不渲染统计挂载点、浏览器不加载统计客户端、不发任何请求；
- 脚本名不合法或文件不存在时不会报错，只会输出控制台警告并按停用处理；
- 数字在浏览器端实时获取，每次页面加载（含 Swup 换页）都会刷新，无需重新构建部署。

## 二、目录结构

```text
src/stats/
├── client.ts          # 框架客户端运行时（勿动）：收集挂载点、缓存、限速、填充数字
├── visitor-stats.ts   # 示例插件：Cloudflare Worker 统计服务实现
└── 使用规则.md         # 本文件
```

## 三、运行机制（框架侧 client.ts 保证）

| 机制 | 说明 |
| --- | --- |
| 埋点上报 | 插件导出 `trackVisit` 时，客户端在每次页面加载（首次整页 + Swup 导航）调用一次，向统计服务记录一次访问（fire-and-forget，不缓存、不限速） |
| 注入时机 | `site.config.ts` 启用时 BaseLayout 注入客户端运行时（仅生产环境，dev 自动不注入不发请求）；每次页面加载（首次整页 + Swup 导航）收集当前页挂载点并填充 |
| 缓存 | sessionStorage + TTL（生产 5 分钟 / dev 1 分钟）：同一浏览器会话内重复访问/换页不重复请求；成功与失败都会缓存（失败为负缓存，TTL 内不重试，避免刷新时反复请求失败的接口） |
| 全站复用 | `getArticleStats` 响应附带 `siteTotal`/`siteUnique` 字段时直接复用，省掉 `/total` 请求（文章页通常 1 个请求即可同时满足文章 + 全站两处显示） |
| 速率限制 | 串行队列 + 相邻请求最小间隔 150ms；插件侧可再做收敛（如 visitor-stats 统一走 `/total` + 插件内 TTL 缓存/in-flight 去重），任意页面每轮至多 1 个统计请求 |
| 失败降级 | 插件抛错 / 请求失败：对应挂载点保留「-」占位，控制台仅输出警告 |

TTL 与请求间隔是 client.ts 顶部的常量（`CACHE_TTL` / `REQUEST_GAP`），可按需调整。

## 四、插件接口契约（必须遵守）

插件是一个普通的 TypeScript 模块，通过命名导出向客户端提供以下可选函数（不需要默认导出）。脚本运行在浏览器端，可以使用 `fetch`，不要使用 Node 专有 API：

### 1. `getSiteTotal()` —— 全站累计（可选）

```ts
export function getSiteTotal(): Promise<{
  siteTotal: number        // 全站累计 PV（访问次数）
  siteUnique: number       // 全站累计 UV（独立访客数）
}>
```

- 渲染位置：个人名片统计卡片（ProfileCard），与「博客总篇数」并列。
- 若不导出此函数，名片不显示全站统计，不影响其他功能。

### 2. `getArticleStats(path)` —— 单篇文章累计（可选）

```ts
export function getArticleStats(path: string): Promise<{
  articleTotal: number     // 文章累计 PV（阅读次数）
  articleUnique: number    // 文章累计 UV（独立阅读数）
  siteTotal?: number       // 可选：附带的全站 PV（提供则免去 /total 请求）
  siteUnique?: number      // 可选：附带的全站 UV
}>
```

- `path` 入参为文章页规范路径，如 `/posts/hello-world`（与语言前缀无关，固定以 `/posts/` 开头）。插件内部可自行做更宽松的规范化，但必须保证能处理 `/posts/xxx` 这种标准形式。
- 渲染位置：文章卡片「前往阅读」徽标左侧（列表页）、文章阅读页头部「阅读时间」之后。列表页多篇徽标的查询由插件统一收敛到单次请求（如 visitor-stats 全部走 `/total` 并做插件内 TTL 缓存 + in-flight 去重），不会逐篇请求打爆统计服务。
- 建议：优先提供一次返回全量数据的接口（如 visitor-stats 的 `/total`，全站 + 全部文章列表一次拿齐）；或接口顺带返回全站数据（客户端会自动复用），把每页请求数压到最低。

### 3. `trackVisit(path?)` —— 访问埋点上报（可选）

```ts
export function trackVisit(path?: string): void
```

- 客户端在每次页面加载（首次整页 + Swup 导航）时调用一次，用于向统计服务记录一次访问（PV 埋点）。不缓存、不限速——每次真实访问都应上报；
- `path` 入参为当前页面路径（`location.pathname`），插件可忽略该参数自行取值；
- 实现必须 fire-and-forget：内部吞掉所有错误（如 `fetch(...).catch(() => {})`），不得向页面抛异常；
- 若不导出此函数，客户端跳过埋点，数字展示不受影响。

### 4. 错误处理约定（重要）

- 请求失败、服务不可达等情况应抛出异常（reject），由客户端统一捕获后隐藏对应统计；
- 不要用返回 `-1`、`null` 等方式表达失败，直接 throw 即可。

## 五、页面挂载点（框架自动处理，插件作者无需关心）

启用后组件渲染 `data-stats` 挂载点，由 client.ts 填充：

| 挂载点 | 位置 | 填充内容 |
| --- | --- | --- |
| `data-stats="site-pv"` / `"site-uv"` | ProfileCard | 全站累计 PV / UV |
| `data-stats="article-pv"` / `"article-uv"`（所在容器带 `data-stats-path="/posts/xxx"`） | PostCard 徽标、PostPage 头部 | 文章累计 PV / UV |

挂载点启用即随页面渲染（初始占位「-」），客户端获取成功填充数字，失败保留「-」。

## 六、编写你自己的插件（示例骨架）

```ts
// src/stats/my-stats.ts —— site.config.ts 填 statsScript: 'my-stats' 即启用

export function trackVisit(path: string = location.pathname) {
  // fire-and-forget：失败静默，不影响页面
  fetch(`https://your-api.example/log?path=${encodeURIComponent(path)}`).catch(() => {})
}

export function getSiteTotal() {
  return fetch('https://your-api.example/site')
    .then((r) => r.json())
    .then((d) => ({ siteTotal: d.views, siteUnique: d.visitors }))
}

export function getArticleStats(path: string) {
  return fetch(`https://your-api.example/page?path=${encodeURIComponent(path)}`)
    .then((r) => r.json())
    .then((d) => ({
      articleTotal: d.views,
      articleUnique: d.visitors,
      siteTotal: d.siteViews,      // 可选，能带就带
      siteUnique: d.siteVisitors,  // 可选
    }))
}
```

注意事项：

1. 三个函数都是可选的，只导出你需要的那些；
2. 脚本只在浏览器端运行，不会在构建期执行，也不会在停用时被打包；
3. 插件可以额外导出仅供服务端使用的辅助函数（如 visitor-stats 的 `getRealtimeStats`），客户端只调用上述三个契约函数，其余导出会被一并打进浏览器包，注意不要在其中嵌入密钥等敏感凭证；
4. 建议服务端接口带短缓存（如 60s），配合客户端 TTL 缓存把请求量降到最低。
